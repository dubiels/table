# List View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a client-side "List view" (flat, sortable, filterable table of tasks) as an alternative to the spatial canvas, matching `docs/superpowers/specs/2026-07-21-list-view-design.md`.

**Architecture:** A new pure logic module (`src/lib/listView.ts`) provides testable sort/filter functions reused by a new self-contained `ListView.svelte` component (filter bar + table + row interactions, local `$state` only). `src/routes/(app)/+page.svelte` gains a bound view-mode select that swaps `ListView` in for `TableCanvas`/`MobileColumns`, independent of the existing mobile breakpoint branch. No backend, schema, or load-function changes — everything consumes the `tasks`/`zones` already returned by `+page.server.ts`.

**Tech Stack:** SvelteKit 5 (runes: `$state`, `$derived`, `$props`), TypeScript, Vitest for unit tests. No new dependencies.

## Global Constraints

- No backend/schema/load-function changes — reuse `tasks`/`zones` from `+page.server.ts`'s existing `load` (spec: "Data model / backend changes: None").
- No persistence for the view choice — plain `$state`, resets to table view on reload; no localStorage, no URL query param (spec: "Chosen approach").
- Reuse existing pure functions `zoneForTask`/`taskCenter` from `src/lib/zones.ts` for category derivation — never reimplement zone-membership logic (spec: "Chosen approach").
- Reuse existing global CSS classes for shared visual language instead of redefining them: `.pill`/`.pill-{priority}` and `.chip-due`/`.overdue` from `src/app.css`, `.btn`/`.btn-ghost` for buttons.
- `ListView.svelte` is self-contained: local filter state, local sort state, table markup and styles all live in that one file (spec: "New files"). The one exception is the new `src/lib/listView.ts` logic module, split out specifically so the sort/filter rules are unit-testable — this repo has no component-testing infra (see `package.json`: `vitest` only, no `@testing-library/svelte`), so pure logic is the only new-code surface that gets automated tests. Everything else gets manual verification, matching the spec's own "Testing" section.
- List view must render correctly at mobile widths too — it replaces `MobileColumns` when explicitly selected, independent of the `isMobile` branch (spec: "Changed files").
- Only one sort field active at a time. Default/initial sort: due date ascending. Entries with no value for the active sort field always sort last, **regardless of direction** (spec states this explicitly for due date; this plan generalizes it to every column for consistency — documented here since the spec doesn't spell it out for the other five).
- Filters compose with AND semantics across category/due-date/priority (spec: "Filters"). Category default: all selected. Due date default: All. Priority default: All.
- Per user's standing instructions: this project is trunk-based (commit straight to `main`, no branches/PRs) and fixes/features are never self-tested by launching a dev server or browser — each task ends with commands to run plus manual steps for the user to check by hand.

  - `type SortDirection = 'asc' | 'desc'`
  - `type DueFilter = 'all' | 'overdue' | 'today' | 'week' | 'none'`
  - `type PriorityFilter = 'all' | 'low' | 'med' | 'high'`
  - `const NO_CATEGORY = 'none'`
  - `type ListFilters = { deselectedCategories: Set<string>; due: DueFilter; priority: PriorityFilter }`
  - `function categoryNameFor(task: Pick<ListTask, 'x' | 'y'>, zones: ListZone[]): string` — owning zone name, or `'—'`
  - `function categoryKeyFor(task: Pick<ListTask, 'x' | 'y'>, zones: ListZone[]): string` — zone name, or `NO_CATEGORY`

  - `function sortTasks(tasks: ListTask[], zones: ListZone[], field: SortField, direction: SortDirection): ListTask[]`

Design note on the category filter: it tracks **deselected** keys (`deselectedCategories`), not selected ones. An empty set means "everything shown" for free — matching the spec's "Default: all selected" without needing to enumerate zone names up front, and a newly-created zone is automatically shown (not accidentally hidden) since it starts absent from the deselected set.

Design note on the "This week" due filter: interpreted as "due date is today through 7 days from today, inclusive" (the spec doesn't pin down the exact window; this is the common reading for a task-list due-date filter).

```ts
import { zoneForTask, taskCenter, type ZoneBounds } from './zones';

export type ListTask = {
	id: string;
	title: string;
	done: boolean;
	priority: string | null;
	dueDate: string | null;
	notes: string | null;
	x: number;
	y: number;
};

export type ListZone = ZoneBounds & { name: string };

export type SortField = 'done' | 'title' | 'category' | 'dueDate' | 'priority' | 'notes';
export type SortDirection = 'asc' | 'desc';
export type DueFilter = 'all' | 'overdue' | 'today' | 'week' | 'none';
export type PriorityFilter = 'all' | 'low' | 'med' | 'high';

export const NO_CATEGORY = 'none';

const PRIORITY_RANK: Record<string, number> = { low: 0, med: 1, high: 2 };

/** The owning zone's name for a task, or "—" for a loose task. */
export function categoryNameFor(task: Pick<ListTask, 'x' | 'y'>, zones: ListZone[]): string {
	const hit = zoneForTask(taskCenter(task), zones);
	if (!hit) return '—';
	return zones.find((z) => z.id === hit.id)?.name ?? '—';
}

/** The filter-bar key for a task's category: its zone name, or NO_CATEGORY when loose. */
export function categoryKeyFor(task: Pick<ListTask, 'x' | 'y'>, zones: ListZone[]): string {
	const name = categoryNameFor(task, zones);
	return name === '—' ? NO_CATEGORY : name;
}

function addDays(dateStr: string, days: number): string {
	const d = new Date(`${dateStr}T00:00:00Z`);
	d.setUTCDate(d.getUTCDate() + days);
	return d.toISOString().slice(0, 10);
}

export type ListFilters = {
	/** Category keys (zone name, or NO_CATEGORY) the user has unchecked. Empty = everything shown. */
	deselectedCategories: Set<string>;
	due: DueFilter;
	priority: PriorityFilter;
};

export function filterTasks(
	tasks: ListTask[],
	zones: ListZone[],
	filters: ListFilters,
	today: string
): ListTask[] {
	return tasks.filter((task) => {
		if (filters.deselectedCategories.has(categoryKeyFor(task, zones))) return false;

		if (filters.due !== 'all') {
			if (filters.due === 'none') {
				if (task.dueDate) return false;
			} else if (!task.dueDate) {
				return false;
			} else if (filters.due === 'overdue' && !(task.dueDate < today)) {
				return false;
			} else if (filters.due === 'today' && task.dueDate !== today) {
				return false;
			} else if (
				filters.due === 'week' &&
				!(task.dueDate >= today && task.dueDate <= addDays(today, 7))
			) {
				return false;
			}
		}

		if (filters.priority !== 'all' && task.priority !== filters.priority) return false;

		return true;
	});
}

function sortValue(task: ListTask, field: SortField, zones: ListZone[]): string | number | null {
	switch (field) {
		case 'done':
			return task.done ? 1 : 0;
		case 'title':
			return task.title.toLowerCase();
		case 'category': {
			const name = categoryNameFor(task, zones);
			return name === '—' ? null : name.toLowerCase();
		}
		case 'dueDate':
			return task.dueDate;
		case 'priority':
			return task.priority ? PRIORITY_RANK[task.priority] : null;
		case 'notes': {
			const notes = task.notes?.trim();
			return notes ? notes.toLowerCase() : null;
		}
	}
}

/** Sorted copy of `tasks`; entries with no value for `field` always sort last, in either direction. */
export function sortTasks(
	tasks: ListTask[],
	zones: ListZone[],
	field: SortField,
	direction: SortDirection
): ListTask[] {
	const mul = direction === 'asc' ? 1 : -1;
	return [...tasks].sort((a, b) => {
		const av = sortValue(a, field, zones);
		const bv = sortValue(b, field, zones);
		if (av === null && bv === null) return 0;
		if (av === null) return 1;
		if (bv === null) return -1;
		if (av < bv) return -mul;
		if (av > bv) return mul;
		return 0;
	});
}
```

```svelte
	import TaskDetailModal from './TaskDetailModal.svelte';
	import {
		categoryNameFor,

		type ListTask,
		type ListZone,
		type SortField,
		type SortDirection

	let { tasks, zones }: { tasks: ListTask[]; zones: ListZone[] } = $props();

	let sortField = $state<SortField>('dueDate');
	let sortDirection = $state<SortDirection>('asc');

	let sorted = $derived(sortTasks(tasks, zones, sortField, sortDirection));

	let openTaskId = $state<string | null>(null);
	let openTask = $derived(tasks.find((t) => t.id === openTaskId) ?? null);

	let today = new Date().toISOString().slice(0, 10);

	function toggleSort(field: SortField) {
		if (sortField === field) {
			sortDirection = sortDirection === 'asc' ? 'desc' : 'asc';
		} else {
			sortField = field;
			sortDirection = 'asc';
		}
	}

	function sortIndicator(field: SortField): string {
		if (sortField !== field) return '';
		return sortDirection === 'asc' ? ' ▲' : ' ▼';
	}

	function priorityLabel(priority: string): string {
		return priority === 'high' ? 'High' : priority === 'med' ? 'Med' : 'Low';
	}

	function handleRowKeydown(e: KeyboardEvent, id: string) {
		if (e.key === 'Enter' || e.key === ' ') {
			e.preventDefault();
			openTaskId = id;
		}
```
